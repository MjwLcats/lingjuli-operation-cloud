# 总体架构

## 运行视图

客户端通过内部 Gateway 访问产品 API，第三方通过 Open Gateway 访问稳定 Open API。业务服务使用 Spring MVC，Gateway 使用 Spring WebFlux。Nacos 提供注册发现，本地开发允许通过 Profile 关闭。

服务分为接入、平台、业务、查询、智能、能力和集成七组。分组用于治理，不允许形成组级共享数据库。

## 数据视图

第一阶段共用一个 MySQL 8 实例，每服务拥有独立逻辑数据库、独立 Flyway 历史和明确的数据所有权。目标状态是每服务使用独立、最小权限的数据库运行账号，禁止跨库授权和跨服务直接读表。

当前已创建 tenant、identity、authorization、organization、store 五个逻辑数据库；它们暂由初始化管理账号完成建库与迁移，服务专用运行账号尚未创建。该差异是待完成的基础设施事项，不能被解释为允许服务共享账号或跨库访问。

Redis 保存会话、短期缓存、幂等键和分布式协调，不是业务事实源。Milvus 仅保存知识切片的向量检索副本，可由 MySQL 中的知识数据重新构建。

## 演进

所有服务均可独立运行；实际部署按业务阶段启用。服务拆分依据独立发布、扩缩容、稳定性、安全和团队所有权，不按页面或菜单数量决定。
